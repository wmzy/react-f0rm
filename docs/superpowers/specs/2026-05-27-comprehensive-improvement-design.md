# react-f0rm Comprehensive Improvement Design

## Overview

Full improvement plan for react-f0rm across three phases: foundation hardening, TypeScript migration, and feature completion.

Current state: early prototype with zero tests, incomplete TypeScript types, and several critical bugs.

---

## Phase 1: Foundation Hardening

### 1.1 Bug Fixes

| Bug | Location | Fix |
|-----|----------|-----|
| `isDirty` semantic error | `src/form.js:202` | Compare `values` vs `initialValues` instead of checking `touched.size > 0`. Add `isTouched` for the original behavior. |
| `ensureValidate` race condition | `src/form.js:279` | Remove early throw in sync loop. Use `waitUntil` to wait for all async validators uniformly. |
| `onSubmit` timing | `src/components/Form.jsx:23` | Change to `await validate(form)` before calling `onSubmit`. |
| `useValidate` render mutation | `src/hooks/validate.js:17` | Move `form.validators.set()` into `useEffect`. |
| `setInitialValues` stale values | `src/form.js:237` | Clear `values` Map when `initialValues` changes. Field-level `initialValue` will re-apply on next render. |
| `get` swallows errors | `src/util.js:13` | Remove empty catch block, let path errors propagate. |
| Stale test eslint config | `test/.eslintrc.js` | Update mocha references to vitest. |

### 1.2 Test Coverage

Test framework: **vitest** with jsdom environment.

Tool stack:
- Test runner: vitest
- DOM environment: jsdom (already configured)
- Hooks testing: `@testing-library/react` `renderHook`
- Component testing: `@testing-library/react` + `@testing-library/user-event`

Test file structure:

```
test/
├── form.test.js        # create, getValue, setValue, getError, setError, validate, reset
├── path.test.js        # normalizePath, various path formats
├── util.test.js        # get, set, isEmpty, isPromise, waitUntil
├── hooks/
│   ├── useForm.test.js
│   ├── useField.test.js
│   └── useValidate.test.js
└── components/
    ├── Form.test.jsx
    └── Field.test.jsx
```

Strategy:
- Pure functions: direct calls, assert return values and side effects
- Hooks: `renderHook` from `@testing-library/react`
- Components: `@testing-library/react` with user interaction simulation

## Phase 2: TypeScript Migration

### 2.1 Migration Strategy

Progressive migration, file by file:

1. Enable `strict: true` in `tsconfig.json`
2. Migrate in dependency order: `util.ts` → `path.ts` → `form.ts` → `context.ts` → hooks → components
3. After each file migration, remove corresponding hand-written types from `index.d.ts`
4. After all files migrated, delete `index.d.ts`, use `tsc` to generate `dist/index.d.ts`

### 2.2 Type Design

```ts
// Form instance with generic
interface Form<T extends Record<string, any>> {
  values: Map<string, any>;
  errors: Map<string, string>;
  touched: Set<string>;
  validators: Map<string, () => void>;
  validating: Set<string>;
  initialValues: T;
  emitter: EventEmitter;
  revalidateOnChange: boolean;
}

// Path type inference (recursive)
type PathValue<T, P> = P extends [infer K, ...infer Rest]
  ? K extends keyof T
    ? Rest extends []
      ? T[K]
      : PathValue<T[K], Rest>
    : undefined
  : P extends `${infer K}.${infer Rest}`
    ? K extends keyof T
      ? PathValue<T[K], Rest>
      : undefined
    : P extends keyof T
      ? T[P]
      : undefined;

// useField explicit return type
function useField<T, P>(options: FieldOptions<T, P>): {
  value: PathValue<T, P>;
  error: string | undefined;
  onChange: (value: any) => void;
  onBlur: () => void;
  name: string;
}
```

### 2.3 Build Adjustments

- Switch Rollup to `@rollup/plugin-typescript` or `rollup-plugin-esbuild`
- `package.json` `types` field points to `dist/index.d.ts` (auto-generated by tsc)
- Delete hand-written `index.d.ts`

## Phase 3: Feature Completion

### 3.1 `useFieldArray`

```ts
function useFieldArray<T>(options: {
  name: Name;
  form?: Form<T>;
}): {
  fields: Array<{ id: string; value: any }>;
  append: (value: any) => void;
  prepend: (value: any) => void;
  insert: (index: number, value: any) => void;
  remove: (index: number) => void;
  swap: (from: number, to: number) => void;
  move: (from: number, to: number) => void;
}
```

- Stable `id` per item (auto-increment counter), avoid index-as-key issues
- Operations update `values` Map and emit `change`

### 3.2 Form-Level Validation

New `validate` option on `Options`:

```ts
interface Options<T> {
  // existing...
  validate?: (values: T) => Record<string, string> | Promise<Record<string, string>>;
}
```

- `ensureValidate` runs field validators first, then form-level `validate`
- Form-level result `{ fieldName: errorMsg }` merges into `errors` Map
- Supports async (returns Promise)

### 3.3 Submission State Tracking

New form state fields:
- `isSubmitting: boolean` — submission in progress
- `submitCount: number` — total submission attempts
- `isSubmitSuccessful: boolean | undefined` — last submission result

Corresponding hooks:
- `useIsSubmitting(form)`
- `useSubmitCount(form)`

`handleSubmit` flow:
1. `setIsSubmitting(true)`
2. `await validate(form)`
3. If errors → `onInvalidSubmit` + `setIsSubmitting(false)`
4. If valid → `await onSubmit(values)` → `setIsSubmitting(false)` + update `isSubmitSuccessful`

### 3.4 Dirty Tracking Fix

- `isDirty` compares `values` vs `initialValues` per field
- New `isFieldDirty(form, name)` — single field change check
- `useIsDirty` / `useIsFieldDirty` hooks
- Add `dirtyFields: Set<string>` to Form state, updated on every `setValueByPath` (add if value differs from initial, remove if same)

### 3.5 Field Unmount Value Preservation

New `shouldUnregister` option on `useField` (default `false`):

```ts
useField({ name: 'email', shouldUnregister: false }) // preserve on unmount
useField({ name: 'tempField', shouldUnregister: true }) // clear on unmount
```

### 3.6 Schema Validation Adapters

No built-in Yup/Zod dependency. Provide adapter functions as separate subpath exports:

```ts
import { zodResolver } from 'react-f0rm/resolvers/zod';
import { yupResolver } from 'react-f0rm/resolvers/yup';

useField({ name: 'email', validate: zodResolver(emailSchema) })
```

Implementation: each resolver is a standalone file in `src/resolvers/` (e.g., `src/resolvers/zod.ts`). `package.json` `exports` map adds `"./resolvers/zod"` and `"./resolvers/yup"` entries. Resolvers are tree-shakeable, zero impact on core bundle size.

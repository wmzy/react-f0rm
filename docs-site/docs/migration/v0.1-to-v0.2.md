# Migrating from v0.1 to v0.2

v0.2 restructures the error model — plain string errors become structured `FieldError` objects — and fixes several behavioral semantics: unregister tombstones, full reset, and native validation gating.

## Breaking changes at a glance

| Area | v0.1 | v0.2 |
|---|---|---|
| Error values | plain strings | `FieldError` `{type, message}` |
| `getError()` | `string \| undefined` | `FieldError \| undefined` |
| `getErrors()` | `string[]` | `{path, type, message}[]` |
| `getFirstError()` | — (new) | first error's message string |
| `setError()` | `string` | `string \| FieldError \| undefined` (strings normalized) |
| `useField()` result | — | `error` (message string) + `errorObject` |
| `onInvalidSubmit` errors | `string[]` | `{path, type, message}[]` |
| Form-level `validate` result | flat string record | nested structures flattened recursively |
| Field unmount | value falls back to `initialValues` | unregistered + tombstone |
| `reset()` | clears errors/touched only | full reset incl. submission state |
| Native validation | not gated | gates submission |

## Error model

### Errors are `FieldError` objects

```diff
 setError(form, 'email', 'Invalid email');
-getError(form, 'email'); // 'Invalid email'
+getError(form, 'email'); // {type: 'custom', message: 'Invalid email'}
+getError(form, 'email')?.message; // 'Invalid email'
```

`setError` still accepts plain strings — they are normalized to `{type: 'custom', message}` — and now also accepts a `FieldError` object; passing `undefined` clears the error:

```diff
-setError(form, 'email', 'Invalid email');
+setError(form, 'email', {type: 'pattern', message: 'Invalid email'});
+setError(form, 'email', undefined); // clear
```

### `getErrors()` entries carry `path`, `type`, `message`

```diff
-getErrors(form); // ['Invalid email', 'Required']
+getErrors(form); // [{path: 'email', type: 'custom', message: 'Invalid email'}, ...]
```

`path` is the user-facing dotted field path (`'a.b'`, `'list.0'`), in insertion order.

### `getFirstError()` returns the message string

New helper for the common "just show something" case — it is also what `validate` rejects with:

```diff
-getErrors(form)[0];
+getFirstError(form); // 'Invalid email'
```

### `onInvalidSubmit` receives structured entries

```diff
 <Form
-  onInvalidSubmit={(errors, values) => errors.forEach(message => log(message))}
+  onInvalidSubmit={(errors, values) =>
+    errors.forEach(({path, message}) => log(`${path}: ${message}`))
+  }
 />
```

### `useField` exposes `error` and `errorObject`

`error` remains a plain message string for display; the structured object is available separately:

```diff
-const {value, onChange, onBlur} = useField({name});
+const {value, onChange, onBlur, error, errorObject} = useField({name});
+// error: 'Invalid email' (string | undefined)
+// errorObject: {type: 'custom', message: 'Invalid email'} (FieldError | undefined)
```

The `useError(form, name)` hook follows the same split: it returns the message string, while `getError` returns the object.

### Form-level `validate` results are flattened recursively

Flat records keep working; nested objects now descend into deeper paths, array values contribute their first non-empty string, and `FieldError`-shaped objects are stored as-is:

```diff
 const form = createForm({
   validate: values => {
-    return {confirm: 'Passwords do not match'};
+    return {
+      confirm: 'Passwords do not match',
+      user: {name: {type: 'required', message: 'Required'}} // sets 'user.name'
+    };
   }
 });
```

## Semantic changes

### Unregister leaves a tombstone

In v0.1, unmounting a field removed its value, so subsequent reads fell back to `initialValues` — a remounted field silently revived its initial value. In v0.2 unmounting still unregisters by default, but the removed path is tombstoned: `getValue` returns `undefined` and `getValues()` omits the key entirely (no fallback, no `key: undefined` entries). Writing a value clears the tombstones on its branch, so remounted inputs that receive input behave normally.

```diff
-// v0.1: unmount 'email', getValues() still contains the initial value
-const {email} = getValues(form); // 'a@b.c' (revived from initialValues)
+// v0.2: unmount 'email', the key is gone for good
+const values = getValues(form); // no `email` key
```

Opt back into the old keep-the-value behavior per field:

```diff
-<Field name="email" />
+<Field name="email" shouldUnregister={false} />
```

### `reset()` resets everything

v0.1 only cleared errors and touched state. v0.2 clears values, errors, touched, validating and tombstones, and resets `submitCount` to 0, `isSubmitting` to false and `isSubmitSuccessful` to `undefined`. Pass new initial values to reset to them:

```diff
-reset(form); // values and submission state survived
+reset(form, {email: ''}); // full reset, optionally to new initial values
```

### Native validation gates submission

`<Form>` now renders `noValidate` (suppressing the browser's built-in blocked-submit UI) but runs `checkValidity()` before custom validators. When a native constraint (`required`, `type=email`, `minLength`, …) fails, `reportValidity()` surfaces it as a native bubble, `onInvalidSubmit` fires, and submit handlers do not run.

```diff
-// v0.1: onSubmit ran regardless of native constraints
+// v0.2: onSubmit/onValidSubmit run only after native + custom validation pass
```

## Other changes worth knowing

- **Path syntax**: quoted subscripts are now parsed — `a["b c"]` and `a['b']` address keys with special characters. Parsed paths are cached, so repeated path strings cost nothing extra.
- **`useFieldArray`** re-renders only for changes touching its own branch (path-prefix filtered subscription) — behavior is unchanged, just faster.
- **Explicit form without a Provider**: `useField`, `useFieldArray` and `useValidate` accept a `form` option, so hooks work outside `<Form>`.
- **`useWatch`** is built on `use-sync-external-store/shim` — tearing-safe under concurrent rendering; React ≥ 16.8 remains the supported range.
- **New tools**: `FieldPath<T>`/`PathValue<T,P>` compile-time path types, `getDirtyFields`/`getTouchedFields` + `useDirtyFields`/`useTouchedFields`, the Standard Schema resolver (`react-f0rm/resolvers/standard-schema`), and `Field`'s `renderError` with automatic `aria-invalid`/`aria-describedby` wiring.

## Migration checklist

- [ ] Replace `getError(...)` reads that display the error with `getError(...)?.message` (or `getFirstError(form)` for the first one).
- [ ] Update `getErrors()`/`onInvalidSubmit` consumers from error strings to `{path, type, message}` entries.
- [ ] Audit code that relied on unmounted fields falling back to `initialValues`; add `shouldUnregister={false}` where values must survive unmount.
- [ ] Check `reset()` call sites: it now wipes values and submission state; pass `initialValues` to reset to fresh defaults.
- [ ] Confirm submit handlers tolerate being skipped when native constraints fail.
- [ ] Optional: adopt `FieldPath`/`PathValue`, the dirty/touched field hooks, the Standard Schema resolver, and `renderError` for accessible error display.

# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

react-f0rm is a lightweight React form library focused on:
- Event-driven architecture using the typed emitter facade (`src/emitter.ts`, a verbatim re-export of the `@for-fun/event-emitter` runtime dependency)
- Field-level subscriptions — a change re-renders only the affected field
- Fine-grained tree-shaking (only pay for features you use, e.g. resolvers are separate entry points)
- Map/Set-based state storage for efficient updates
- TypeScript source with full type coverage

## Comment Discipline

Comments are a maintenance cost — the codebase is kept deliberately lean, and any change that grows them back is a defect. New code and reviews follow these rules:

- Public API JSDoc: 1–3 lines of essentials (what it does / the contract). No narrative paragraphs, no obvious `@param`/`@return` — only non-obvious parameter semantics (defaults, interactions, edge behavior).
- Inline comments: only non-obvious invariants and "why", never "what" — a comment that restates the code is deleted, not kept. What survives: emit-ordering requirements (e.g. "errors land before the validating mark releases"), StrictMode snapshot/restore rationale, tombstone semantics, path-key trailing-comma prefix matching, key-pinned subscriptions (react-compiler constraint), cache version-bump rationale.
- No orphaned doc blocks (doc with no attached symbol) and no duplicate docs — a concept is documented once; facade re-exports never re-document.
- When code moves or changes, its comments move or get deleted with it — never leave a drifting doc.
- Density bar: `src/core/validate.ts` is the reference for internal modules; a PR adding comment lines beyond this bar gets flagged in review.

## Architecture

### Core Layer (`src/form.ts`, `src/core/`)
Pure functions operating on a Form state object. `src/form.ts` is the facade: all public types, the `create` factory, and `export *` re-exports of the implementation modules. The implementation is split by concern under `src/core/` — `values.ts` (getValues/setValue/reset/removeField/setInitialValues/getFieldState), `array.ts` (framework-free array movers `appendValue`/`prependValue`/`insertValue`/`removeValue`/`moveValue`/`swapValues`/`replaceValues`/`updateValue`, each with a `*ByPath` variant — the headless counterparts of `useFieldArray`'s operations, which are thin wrappers adding only row-id bookkeeping; `removeValue` takes one index or a list and returns the dropped indices descending, guarded movers report `false`/`[]` instead of writing), `errors.ts` (errors Map ops, `FORM_ERROR`, the `VALIDATION_OUTCOME` brand, the memoized `getErrorsRecord` — the version-bumped cache behind `useErrors`/`useFormState().errors` — plus the exported `DottedPath<P>` type and the `fieldPathToDottedKey`/`dottedKeyToFieldPath` converters bridging the record's dotted keys and the bracket path spelling every field API takes), `touched.ts`, `dirty.ts`, `validate.ts` (field/form validator machinery, trigger/ensureValidate), `change.ts` (the user-change pipeline + field-mode registry), `submit.ts` (submission state + handleSubmit), `focus.ts` (setFocus) — plus `internals.ts`, which holds module-private cross-cutting state (values/dirty caches, committed dirty baselines, isFieldError/isSegmentsPath, setParsedValues) and is deliberately never re-exported by the facade. The event emitter is a facade (`src/emitter.ts`) re-exporting `@for-fun/event-emitter` — a shared runtime dependency (same author), kept **external** in every ESM/CJS build output so an app that already depends on it dedupes the copy; only the self-contained UMD bundle inlines it. The dependency-vs-vendor decision is recorded in `docs/decisions/0001-event-emitter-facade.md` (ADR-0001) — do not re-litigate it per session; new emitter events extend the `FormEvents` table first. `useSyncExternalStore` comes from React itself. The dependency graph is acyclic: internals/errors/touched are leaves; values → errors/touched/internals; array → values; dirty → internals; validate → values/errors/touched/focus/internals; change → values/validate/touched/errors/internals; submit → validate/errors/values. `useWatch` is built on React's native `useSyncExternalStore` — the peer range is `react >=18`.
- `values: Map<string, any>` — field values keyed by JSON-serialized path
- `errors: Map<string, FieldError[]>` — validation errors, one non-empty array per field key; `FieldError` is `{type, message}` (`type: 'custom'` for plain string errors)
- `deleted: Set<string>` — tombstones of unregistered paths: reads and `getValues()` must not fall back to `initialValues` for these paths
- `touched: Set<string>` — touched field tracking
- `validators: Map<string, () => void>` — per-field validation kicks, registered through the framework-free `registerValidatorByPath` (`useValidate` is its React-side wrapper: debounce window, async-round lock + AbortSignal, sync gate, validating mark)
- `validating: Set<string>` — in-flight async validators
- `emitter` — event emitter for reactive updates, typed with a `FormEvents` table (`change`/`errors`/`touched`/`validating` carry an optional `Path` payload, `focusError` carries `[key, options?]`, the rest — including `loading`, `status` and `disabled` — are payload-less); listener cap raised to unlimited at create (`setMaxListeners(emitter, 0)`) — a form legitimately holds one listener per mounted field per event
- `validate` — optional form-level validator
- `mode: ValidationMode` / `reValidateMode: ReValidateMode` — validation timing (resolved defaults at create: `'onSubmit'` / `'onChange'`)
- `isSubmitting`, `submitCount`, `isSubmitted` (set on every submit attempt, cleared by reset — RHF `formState.isSubmitted`), `isSubmitSuccessful` — submission state
- `isLoading: boolean` — true while an async `initialValues` source (Promise, or thunk returning one) is pending; flips through the `'loading'` event and lands the resolved values via `setInitialValues` (RHF async `defaultValues` shape)
- `status: any` — user-owned metadata slot (Formik `status` role: session flags, wizard step state, non-field errors); written via `setStatus` (payload-less `'status'` event), read reactively via `useStatus`
- `validateOnMount: boolean` — form-level default for mount validation (Formik `validateOnMount` / TanStack per-field flag): mounted fields with a validator kick once after mount, `useForm` runs the form-level `validate` once; kicks defer behind an async `initialValues` source and a field's own option overrides the flag in either direction
- `asyncAlways: boolean` — form-level default for field validation's asyncAlways (TanStack namesake): when true, a field whose `required` gate failed still runs its debounced validator, both verdicts landing per-source; a field's own option overrides in either direction
- `shouldUseNativeValidation: boolean` — form-level flag (RHF namesake, default true): native constraint validation gates submission (skipped for targets without `checkValidity`) and a bound `Field` skips its custom validator on a native-failing kick; seeded from `Options.shouldUseNativeValidation`, fixed at create, per-attempt override via `HandleSubmitOptions.shouldUseNativeValidation`
- `shouldUnregister?: boolean` — form-level default for a field's unmount behavior (true = tombstone, the historical default; false = keep value, RHF semantics); a field's own `shouldUnregister` option overrides

Key exports: `createForm`, `getValues`, `getValue`, `setValue` (4th `options?: SetFieldOptions` — `shouldValidate`/`shouldTouch` default false; `shouldDirty: false` commits the write: the value becomes the field's dirty baseline via a module-private `dirtyBaselines` WeakMap, cleared by reset/setInitialValues/resetField/removeField and pruned by ancestor-path writes; the value may be an updater `(prev) => next` — TanStack `setFieldValue` contract, so a function can never itself be stored as a value), `changeValue`/`changeValueByPath` (user-change channel: rides the core's gated pipeline when a field is mounted at the path, plain `setValue` fallback otherwise), `userChangeByPath`/`userBlur` (the bound-field change/blur pipeline itself: write/touched marking plus the mode/reValidateMode-gated validation kick, form-level and field-level `validateDeps` re-runs — framework-free, headless adapters call them directly; `useField`'s onChange/onBlur forward here), `registerFieldMode`/`unregisterFieldMode` (mounted fields register their per-field `mode` override in a module-private WeakMap — presence is the "a field is mounted here" signal `changeValueByPath` routes through), `registerValidatorByPath` (framework-free validator registration: debounce windows, async-round lock, sync gate, validating mark — the machinery behind `useValidate`), `getError`, `getErrors`, `getFirstError`, `setError` (4th `options?: SetErrorOptions` — `shouldFocus` emits `'focusError'` for the named key after the error lands), `clearErrors`, `setTouched`, `hasTouched`, `isDirty`, `isFieldDirtyByPath` (the shared per-field rule behind `getFieldState().isDirty`/`useIsFieldDirty`: a live value exists at the path and differs from its effective baseline; leaves under a wholesale ancestor write report clean — dirtiness belongs to the branch), `getDirtyFields`, `getTouchedFields`, `isTouched`, `removeField` (third `options?: RemoveFieldOptions` — `keepValue`/`keepDirty`(implies keepValue)/`keepTouched`/`keepError`, RHF `unregister` names), `setInitialValues`, `reset` (options add RHF-parity `keepValues` (every current leaf, clean baseline fields included, written back over the new baseline), `keepDefaultValues` (ignore a provided baseline), `keepIsSubmitted` (the submitted flag), `keepIsSubmitSuccessful`, `keepSubmitCount`, `keepIsSubmitting`, `keepTouched`, `keepErrors` beside `keepDirtyValues`), `trigger` (third `options?: TriggerOptions` — `shouldTouch` marks the triggered scope touched; `shouldFocus` focuses the first errored triggered field via the 'focusError' channel), `FORM_ERROR` (exported constant `'_form'`: the reserved top-level segment for form-level errors — the Standard Schema form validator's landing slot for path-less issues; read it via `getError(form, FORM_ERROR)`/`setError(form, FORM_ERROR, …)` instead of the magic string), `ensureValidate`, `validate`, `handleSubmit` (headless submit handler taking `{onSubmit, onValidSubmit, onInvalidSubmit, onAction, shouldFocusError}` — sets `isSubmitted` on every attempt, clears previous round-trip `type: 'server'` errors first (`clearServerErrors`: a fresh attempt supersedes the old verdict; client errors still gate), `onAction` runs last with the final values and may return `ActionErrorResult` (`{errors: {path: msg}}`) — landed as per-field `type: 'server'` errors via setServerErrors, submit marked unsuccessful; `<Form>`'s `action` prop uses it to dispatch `formDataFromValues(values)`), `setServerErrors` (lands a server error record `Record<string, string | string[]>` as per-field `type: 'server'` errors; clears existing first unless `keepExisting`), `setStatus` (writes the form's user-owned metadata slot, emits the payload-less `'status'` event; the Formik `status` role for session flags/step state/non-field errors), `runFormValidate` (form-level-only validate round, field validators excluded — `trigger`/`ensureValidate` compose it after fields settle; `useForm`'s `validateOnMount` run uses it), plus types `ValidationMode` (`'onSubmit'|'onBlur'|'onChange'|'onTouched'|'all'`), `ReValidateMode` (`'onChange'|'onBlur'|'onSubmit'`, effective only while the field already has an error), `SetFieldOptions`, `SetErrorOptions`, `HandleSubmitOptions`, `RemoveFieldOptions`, `FieldError`, `FieldErrorEntry`, `Validator`, `SyncValidator`

`getValues` merges the values Map over `initialValues` with copy-on-write ownership tracking (`setOwned` in util.ts): each distinct container on a written path is allocated once and shared by all paths through it, then removes tombstoned paths immutably (`unset`). Memoized per form through a module-level `valuesCaches` WeakMap (the same version-bump/read pattern `getDirtyFields` uses): every value-mutating entry point (setValueByPath, removeFieldByPath, setInitialValues, reset, resetField, setParsedValues) bumps a version counter, so consecutive reads share one reference — the result is read-only shared between writes. Under `__DEV__` the computed result is clone-then-frozen (`freezeValues` in util.ts: plain objects/arrays cloned + frozen so consumer mutations throw at the offending site; Date/File/class instances pass through by reference) — production builds share the baseline references exactly as before.

Generation semantics of whole-branch writes: `setValueByPath` at a path P drops the values Map keys under P (they belong to a replaced generation — they would shadow the new value on exact-key reads or re-apply over it in `getValues`' insertion-ordered merge), and `getValueByPath` resolves a missing key through the nearest live ancestor entry before falling back to `parsedValues ?? initialValues` — so leaf readers (`useField` at `items[0].name`) follow a wholesale replace (`setValue(form, 'items', …)`, every `useFieldArray` operation) instead of seeing the pre-edit snapshot. Paths the ancestor's value does not carry read `undefined`; the baseline never fills holes inside a replaced branch. `set`/`setOwned` copy with the array rule for numeric segments in either form (numbers from bracket syntax, or index-shaped strings from programmatic segment arrays), so merging into an array branch keeps it an array.

`getDirtyFields` is memoized per form through a module-level `dirtyFieldsCaches: WeakMap<Form, DirtyFieldsCache>`: `setValue`/`reset` etc. bump a `version` counter (mutation since last compute) while reads reset it and cache the result — a non-zero version means stale, so the next read recomputes.

### Path System (`src/path.ts`, `src/util.ts`, `src/types.ts`)
- `src/path.ts` — `create(name)` returns a `Path` `{value: segments, key: JSON-stringified segments}`; `key` is the Map/Set lookup key
- `src/util.ts` — `parsePath` tokenizer accepts dotted (`a.b`), bracket (`a[0]`, `a["b c"]`, `a['b']`) syntax; numeric segments are bracket-only (`items.0` throws a `TypeError` suggesting `items[0]`), and a quoted segment (`items["0"]`) keeps an explicit string key. `normalizePath` caches parsed strings in a module-level `pathCache` Map (throwing paths are never cached); the cache is FIFO-bounded at 1e4 entries — a backstop for dynamic keys only, since eviction just costs a re-parse and never changes behavior. Also `get`/`set`/`unset`/`setOwned` immutable tree helpers
- `src/types.ts` — compile-time path types: `FieldPath<T>` enumerates valid path strings for a values shape (capped at 10 segments — deeper paths fall back to `any` through `PathValueOf` rather than erroring), `PathValue<T, P>` resolves the value type at a path, `OpaqueTypes` is an opt-in registry of leaf types (`declare module 'react-f0rm' { interface OpaqueTypes { dayjs: Dayjs } }`) that stop path recursion — Date/Dayjs/class-instance values are values, not field trees (RHF 7.87's same-named registry), `ArrayItemOf<T, P>` resolves the element type of the array a path points at; includes self-check types verified by `tsc --noEmit`

### Hooks Layer (`src/hooks/`)
- `useForm` — creates the form instance via `useState` lazy initialization (stable across re-renders and StrictMode double renders), syncs `initialValues` through `setInitialValues` in an effect (function/Promise sources are skipped there — `createForm` owns their one-shot async resolution: the form starts empty with `isLoading: true`, flips through the `'loading'` event, and lands the resolved values via `setInitialValues`; `useIsLoading` / `useFormState().isLoading` expose the flag); an extra `values` option enables controlled usage — changed content re-syncs (setInitialValues semantics: uncommitted edits discarded, touched/errors kept) while equal content never re-syncs (structural comparison, so inline literals per render never clobber typing)
- `useField` — combines value, error (`error`: message string, `errorObject`: `FieldError`), touch state + onChange/onBlur handlers; onChange/onBlur are thin forwards to the core's `userChangeByPath`/`userBlur` (write/touched + mode/reValidateMode-gated validation lives entirely in core); returns the bound `form` for direct headless access; accepts an explicit `form` option (no Provider needed); `uncontrolled: true` pins the value at mount and skips the value subscription — typing re-renders nothing (RHF `register`-style; the store still carries every write, errors/touched/disabled/validating still re-render the field; a payload-less `'change'` — reset/setInitialValues bulk operations — writes the store's value straight into the element held by `focusRef`, register-style with no render, file inputs exempt; reset/initialValues do not push into the pinned snapshot itself); the result also carries `isDirty` (the shared per-field rule `isFieldDirtyByPath` — live in controlled mode via the same leaf-scope 'change' subscription, pinned at mount in uncontrolled mode like `value` so typing never re-renders; `useIsFieldDirty` is the live scoped channel for either mode) and `validating` (exact-key 'validating' subscription, always live); the `validate` option's value argument is path-typed (`PathValueOf<TValues, TPath>` — TanStack-parity inference; `any` for untyped call sites), and `validateOnMount` (field option or form-level `createForm({validateOnMount})`) kicks the validator once after mount — deferred behind an async `initialValues` source, and validator-less registrations never kick (an empty kick would clear a pre-mounted server error); `rules` (declarative `FieldRules`: required/min/max/minLength/maxLength/pattern plus `validate` callbacks — RHF `register({validate})` shape, one fn or a record, errors typed by the key, running after the declarative checks) compile into a sync validator composed ahead of `validate`, with `required` split into useValidate's sync gate (runs immediately every kick, never debounced, short-circuits the rest while failing); `asyncAlways` (field option or form-level `createForm({asyncAlways})`) makes the debounced validator still run when that gate failed, landing its result alongside the gate's errors per-source; `validateDeps` declares field-to-field linkage — listed paths' user changes re-run this field's validator through `revalidateDependentsOnChange` (per-form `fieldValidateDeps` WeakMap registry, same mode matrix as the form-level option); `initialValue` seeds during render (`seedValueByPath` — an emit-free write) so the first paint and SSR carry it, with a post-commit `emitChangeByPath` announce per actual seed; on unmount the effective `shouldUnregister ?? form.shouldUnregister ?? true` decides tombstone vs keep-value (form-level `createForm({shouldUnregister})` flips the default, the field's own option overrides); the result carries `focusRef` — an identity-stable callback ref subscribing to the `'focusError'` event from inside `useFieldCore` (headless `setFocus`/failed-submit auto-focus channel; `<Field>` just forwards it through its merged ref, it no longer owns its own subscription)
- `useFieldArray` — array field operations (append/prepend/insert/remove/swap/move/replace/update); `remove` takes one index or a list (`remove([0, 2])` — several rows drop in one write, order-insensitive, duplicates ignored), guarded movers are silent no-ops on out-of-range indices (values, row ids and render count all untouched), and a `useFieldArray<Item>({name})` generic types every mover's value argument against the array's element type (defaults to `any`). The movers are thin wrappers over the framework-free core ops in `src/core/array.ts` (which report the dropped indices / a success boolean so the ids stay in lockstep); subscribes to `change` events with path-prefix filtering so only changes touching its branch re-render it. Options: `keyName` (stable row id's property name on `fields` entries, default `'id'`), `rules` (`FieldRules` validated against the whole array — `required` fails on `[]`, `minLength`/`maxLength` read array length; wired through `useValidate` with the required sync-gate split), `shouldUnregister` (unmount → `removeFieldByPath` when `(shouldUnregister ?? form.shouldUnregister) !== false`, the same effective expression as `useField`)
- `useFieldArrayItem` — per-row subscription for large arrays (TanStack field-api counterpart): resolves a row by its stable `id` through a module-level `arrayIdsRegistry` WeakMap (the paired `useFieldArray` publishes its live ids array there — render-time for SSR, re-registered in the effect because StrictMode exercises the cleanup path without a fresh render); index+value are read synchronously at render from the array layer and re-validated in the listener (a render is dispatched only when the row's own index or value reference changed — React's equal-state bailout is not honored under act), errors subscribe to the exact row key. Single-row edits re-render only that row; index migrations (reorder/remove) re-render by design
- `useValidate` — React-side wrapper around the core's `registerValidatorByPath`: registers the field's kick in `form.validators` (debounce window, async-round lock + AbortSignal, sync gate, validating mark all live in core; the hook only wires mount/dispose lifecycle and refs that keep the validator/debounce/sync/asyncAlways options live across re-renders without re-subscribing mid-flight); `validateOnMount` schedules the kick once after the registration lands (deferred behind `form.isLoading` so an async `initialValues` source is validated after its baseline lands; a disposed registration never fires its deferred kick — StrictMode-safe); `asyncAlways` — an optional accessor on the framework-free `ValidatorRegistration` (absent = false, so pre-existing callers compile unchanged) — keeps the debounced validator running when the sync gate failed: gate errors land immediately, the validator's result lands alongside them per-source (`land` in core re-collects the gate's verdict and merges; the non-asyncAlways path keeps the historical "validator owns the whole key" write)
- `useTransform` — TanStack `useTransform` counterpart with the round trip split into two explicit directions: `toDisplay` maps the store's raw value to the control's display value, `fromDisplay` maps it back on write (both optional → identity); the store always carries the raw typed value, so getValues/submit/validation never see display representations. `value` subscribes to 'change' at leaf scope like a controlled `useField` value; `onChange` writes through `userChangeByPath` — with a field mounted at the same path the mode/reValidateMode-gated validation fires as if the user typed (validators receive the raw value), with no mounted field it degrades to a plain `setValue` write. `fromDisplay` may return a Promise (async transforms); `asyncDebounceMs` debounces the display→raw commit — latest write wins, stale resolutions dropped via a sequence token (TanStack `asyncDebounceMs` parity), the commit rides `userChangeByPath` so validation fires at commit time. Headless: explicit form argument, no context read. Lives in `src/hooks/transform.ts`
- `useWatch` — built on React's native `useSyncExternalStore` (tearing-safe; peer range React ≥ 18); first argument is the form (unified `fn(form, ...)` context shape; the raw emitter remains accepted for back-compat); caches the getter snapshot per hook instance and invalidates it on the watched event; optional 4th `isEqual` argument (TanStack `useSelector` compare contract) recomputes on event and skips `notify()` entirely while the projection is equal — broad-scope custom getters returning fresh-but-equal references stop re-rendering
- `useValue`, `useError`, `useTouched`, `useIsDirty`, `useIsFieldDirty` (per-field dirty via the shared `isFieldDirtyByPath` rule, leaf-scope 'change' subscription), `useDirtyFields`, `useTouchedFields`, `useHasErrors`, `useIsValid` (`!hasErrors`, RHF `isValid` semantics — in-flight validation does not flip it), `useErrors` (every error as one typed `FieldErrors<T>` record keyed by the runtime dotted path — RHF `FieldErrors` shape; per-key `FieldError[] | undefined`, the `FORM_ERROR` slot included; array keys are dot-joined (`'tags.0'`) while `FieldPath` spells brackets — the exported `DottedPath<P>` type names the key style and `fieldPathToDottedKey`/`dottedKeyToFieldPath` convert between the spellings; memoized through the version-bumped `getErrorsRecord` cache, so the hook re-renders only when an error write changed content), `useValues` (whole-tree 'change' watch, RHF `watch()` no-args; the memoized `getValues` snapshot), `useStore` (the selector primitive: subscribes to every state-bearing event, `selector()` closure + optional `isEqual` bailout — TanStack `useStore(store, selector)` counterpart; `useFormState` is the built-in aggregate selector, `useWatch` the single-event version), `useIsSubmitting`, `useSubmitCount`, `useIsValidating` (`form.validating.size > 0`: field async/debounce windows plus the form-level round), `useIsSubmitSuccessful`, `useFormError`/`useFormErrors` (read the `FORM_ERROR` key), `useStatus` (the form's user-owned metadata slot — `setStatus` writes it, payload-less `'status'` event drives it), `useFormState` (one subscription, one reference-stable aggregate snapshot: isDirty/dirtyFields/isTouched/touchedFields/hasErrors/isValid/errors/isSubmitting/isValidating/isSubmitSuccessful/submitCount/disabled; generic — `FormState<T>` types `errors` as `FieldErrors<T>`; field-wise comparator skips re-renders while nothing observably changed), `useCanSubmit` — state hooks built on `useWatch`. `useValue(form, name, options?)` carries RHF-parity options: `defaultValue` (returned while the field reads `undefined`) and `exact: false` (branch scope — descendant writes invalidate the read, which then resolves the merged subtree through `getValues`, since `getValueByPath` only walks live ancestors and would otherwise return a stale reference); the default leaf scope is unchanged

### Components (`src/components/`)
- `Form` — context provider, handles submission/validation flow with submission state tracking; native constraint validation gates submission (checkValidity() before custom validators, reportValidity() bubbles on failure; the element renders `noValidate`); accepts `values` for controlled external sync, `shouldFocusError` (default true), `disabled` (form-level flag — seeded at create and kept in sync with the prop through `setDisabled`, `undefined` leaves the flag untouched), `asyncAlways` (form-level default for fields' asyncAlways) and an `action` prop — after validation passes (and after onSubmit/onValidSubmit), the validated values are converted to `FormData` (`formDataFromValues`) and dispatched to it, e.g. a React 19 Server Action; the action may return `ActionErrorResult` (`{errors: {path: msg}}`) — landed as per-field `type: 'server'` errors, submit counts unsuccessful; `action` also accepts a URL string rendered as the native `action` attribute for progressive enhancement (no-JS posts raw FormData, JS runs the validated pipeline)
- `FormField` — headless render-prop counterpart of `useField` (`{children: field => …}`, Formik `<Field>` shape) for class components and library bridges
- `Field` — controlled input; `type="file"` inputs are special-cased: no `value` prop ever (files cannot be value-controlled), the picked `FileList` is written into the form store so getValues/submit/validation carry it; `valueAsNumber`/`valueAsDate` store `e.target.valueAsNumber`/`valueAsDate` instead of the string (RHF `register` options; `eventToValue` wins, both together warn in DEV and number wins); `rules` render the declarative subset as **native constraint attributes** (`rulesToConstraintAttrs`: required/min/max/minLength/maxLength/pattern → DOM attrs; `validate` callbacks skip) spread *before* user props so a user-passed attribute always wins — the attrs serve a11y/`:invalid` styling only, the store pipeline stays the message source (rules run ahead of the validate wrapper, whose checkValidity gate now also sees derived attrs and skips the user `validate` for that kick — RHF first-error semantics); `uncontrolled` renders `defaultValue` instead of `value` (DOM sync on bulk operations rides useField's focusRef channel); on error sets `aria-invalid` and appends `fieldErrorId(name)` to `aria-describedby` (exported `fieldErrorId` is the library-wide convention: any error element rendering that id completes the screen-reader chain); with the `renderError(error, id)` prop renders `<span id role="alert">` itself; user-provided `aria-describedby` is preserved (error id appended after); mirrors custom errors onto native validity via `setCustomValidity`; subscribes to the form's `'focusError'` event to focus its input when a failed submit names it as the first error
- `Checkbox`, `Radio` (`Group`/`Item`) — group/item components for multi-select and single-select
- `Select` — controlled `<select>` with options as children; single-select stores a string value, `multiple` stores the selected options' values as a string array

### Subscriptions (`src/subscribe.ts`)
Path-scoped event subscription primitives — the reason a keystroke stays O(affected fields) instead of O(all subscribers):
- `onPathEvent(emitter, event, path, scope, cb)` — `leaf` scope fires for writes at the path itself or an ancestor; `branch` scope additionally fires for descendants (array sections). Payload-less emits (reset, setInitialValues) always fire — the correctness fallback.
- `onKeyEvent(emitter, event, key, cb)` — exact-key match or payload-less; used by error/touched watches. Ancestor/descendant tests compare JSON path keys with a mandatory trailing comma so `["tagsX"]` never prefix-matches `["tags"]`.
- `watch(form, event, getter, isEqual?)` — the framework-free counterpart of `useWatch`: a tree-shakeable named export returning a `WatchHandle` (`getSnapshot`/`subscribe`/`dispose`). Eager internal listener keeps the snapshot always fresh; the `isEqual` bailout skips consumers while the projection is unchanged (TanStack `useSelector` contract).
- Emit sites that mutate a single path carry the `Path` payload (`setValueByPath`, `removeFieldByPath`, `setErrorByPath`, `setTouchedByPath`, `setValidating*`); bulk operations (reset, setInitialValues, clear-all) emit payload-less so every subscriber resyncs. The public `subscribe` event union is `'change' | 'errors' | 'touched' | 'validating' | 'submitting' | 'submitCount' | 'submitSuccessful' | 'disabled'` — `'validating'` carries paths (routed like `'change'`), the rest of the tail is payload-less broadcasts; routing is a blacklist (`errors`/`touched` → `onKeyEvent`, everything else → `onPathEvent`).

### Resolvers (`src/resolvers/`, `src/standardSchema.ts`)
- `src/resolvers/standard-schema` — thin re-export of the shared leaf below: `standardSchemaResolver` (field-level) and `standardSchemaFormValidator` (form-level; issues without a path land on the `FORM_ERROR` key); also re-exports `InferSchemaValues`
- `zodResolver` / `yupResolver` — adapt Zod / Yup schemas
- `src/standardSchema.ts` — framework-free leaf holding the structural Standard Schema v1 contract, `hasStandardProps`, `schemaToFieldValidator`/`schemaToFormValidator`, `InferSchemaValues`; the core accepts a schema directly in `createForm({validate})` (wrapped automatically, `TValues` infers from the schema output) and `useField`/`Field({validate})` (field-level schemas validate only — never rewrite the value)

### Server entry (`src/server.ts`)
`react-f0rm/server` — tree-shakeable entry importing only from `./form` (zero React in the module graph, RSC/Server Action safe): `validateValues(values, options?)` runs one whole-form validation round over a plain payload (`createForm` + `trigger`, never rejects) and returns `{valid, values, errors}` where `values` carries schema-coerced output (the `parsedValues` baseline) and `errors` is the flat `FieldErrorEntry[]` list; `formDataFromValues(values)` converts a values tree into `FormData` (arrays → multiple entries, File/FileList passthrough, Date → ISO string, objects → JSON, null/undefined skipped) — the converter `<Form action>` uses to dispatch React 19 Server Actions; `valuesFromFormData(formData)` is its inverse for the server side of that round trip (repeated keys → arrays, JSON-looking strings → objects, everything else stays a string for schema coercion, Files passthrough) — pair it with `validateValues` for a hand-rolled-`.get()`-free Server Action; re-exports `VALIDATION_OUTCOME`/`ValidationOutcome` so branded outcomes can be built server-side.

### Persistence entry (`src/persist.ts`)
`react-f0rm/persist` — React-free side entry: `persistForm(form, {key, storage?, serialize?, deserialize?})` hydrates a stored snapshot via `setInitialValues` (restored values become the clean baseline) and re-writes `getValues()` on every 'change' event through `subscribe`; defaults to `window.localStorage`, silently no-ops without storage (SSR), swallows corrupted payloads. Returns the unsubscribe function.

### Devtools (`src/devtools/`)
`<Devtools form? position? />` — live state panel (values/errors/touched/dirty tabs plus a `submits` tab tracing the 10 most recent completed attempts — outcome, final values, errors, snapshotted on the isSubmitting true→false transition — and an `events` tab streaming every emitted form event, newest first, capped at 50, with path payloads and a Clear action; submit status strip; Reset & Validate actions) shipped behind its own tree-shakeable entry `react-f0rm/devtools` (never imported by the main entry). No extra dependencies: styles are injected once via an idempotent `<style>` element; data flows through the same public hooks/`useWatch` aggregates; the timeline subscribes through the emitter directly (`on`) and setState rides the event callbacks, never the effect body. Collapses to a corner badge (red dot when errors exist).

Tests use Vitest with jsdom environment. Test files are in test/ directory with `.test.{ts,tsx,js,jsx}` extension; the core suite is split by module under `test/core/` (values/errors/touched/dirty/validate/submit/focus/subscribe/createForm — one file per `src/core` concern, no shared module-level helpers) and `test/ui-integration.test.tsx` runs the antd/MUI/Radix/shadcn cookbook adapters from docs-site/docs/guides/ui-integration.md (the three UI libs are devDependencies used only there; antd's jsdom `matchMedia` polyfill is scoped to that file); `test/types.test-d.tsx` is tsc-only (wired into tsconfig `include`, matches no vitest pattern) — it carries the compile-time assertions including the goal-6 typo-rejection checks. The suite runs on the `vmThreads` pool (per-file jsdom isolation with thread reuse — ~7.2s → ~2.8s; the one jsdom-vs-node conflict is the devtools SSR guard, covered by `test/devtools/ssr.test.js` with `@vitest-environment node` instead of stubbing `document`, which vmThreads' jsdom exposes as a non-configurable getter). Benchmarks live in `test/bench/*.bench.ts`, run with `npx vitest bench --run …`: vitest 5 removed the top-level `bench` import — benches register through the test-context fixture inside a regular `test()` (`await bench(name, fn).run({time, warmupTime})`); `vitest bench` discovers `*.bench.*` files itself, they are NOT part of the unit-suite include. Run benches alone — a concurrent unit-suite run inflates rme into the hundreds of percent. ## Key Patterns

- All form operations are pure functions — hooks add React reactivity via event subscriptions
- Path objects enable efficient Map-based lookups instead of deep object traversal; `usePath` memoizes with a two-layer `useMemo` keyed on `path.key` so fresh name arrays reuse the cached Path object
- Validation is async via `ensureValidate`/`validate` with event-driven completion tracking
- Validation timing is governed by `mode`/`reValidateMode` (useField's onChange/onBlur guards): mode `'onTouched'` validates on first blur then on every change; `reValidateMode` supplements any mode but only while the field currently has an error
- `ensureValidate` runs field-level validators first, then form-level `validate` if provided; its result is flattened recursively (nested objects descend into deeper paths)
- `setError` accepts `string | FieldError | undefined`; strings are normalized to `{type: 'custom', message}`
- `useField` unregisters on unmount by default, leaving a tombstone so the value does not fall back to `initialValues`; pass `shouldUnregister: false` per field — or `createForm({shouldUnregister: false})` / `<Form shouldUnregister={false}>` for the form-wide RHF-style default — to preserve the value instead
